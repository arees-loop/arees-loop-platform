## النتيجة

الإصدار **غير جاهز للنشر التجاري بعد**. توجد فجوة عزل في إعداد Vercel: متغيرات اتصال قاعدة البيانات نفسها مستهدفة لكل من Preview وProduction. أضيف إلى فرع المراجعة حارس برمجي يجعل Preview يرفض الاتصال ما لم يضبط اتصال قاعدة مستقلة صراحة، كما يمنع `prisma.config.ts` تحميل `.env.local` كمسار التفافي في Preview. يلزم اعتماد التغيير واختباره في CI، ثم إعداد قاعدة Preview منفصلة قبل إعادة تفعيل معاينات التطبيق. لم يتغير إعداد Vercel.

قاعدة الإنتاج لم تُقرأ أو تُكتب في هذه المراجعة. لا تتوفر أدلة كافية على اتصال Prisma Postgres الفعلي بمشروع الإنتاج أو وجود نسخة احتياطية قابلة للاستعادة؛ إعداد التكامل الذي ظهر بحالة Free لا يحدد قاعدة إنتاج متصلة. لا يمكن اعتماد خطة ترحيل إنتاج قبل التحقق من قاعدة البيانات الصحيحة والنسخ الاحتياطي والاستعادة على نسخة مستقلة.

## ما تغير في هذه المراجعة

- `lib/database-target.mjs`: اتصالات Preview تتطلب `AREES_DATABASE_ENV=preview` و`AREES_PREVIEW_DATABASE_URL` و`AREES_PREVIEW_DATABASE_HOST` وتُرفض إذا طابقت `DATABASE_URL`.
- `prisma.config.ts`: لا يحمل `.env.local` داخل Preview، فيمنع تجاوز الحارس بقيمة محلية.
- `tests/staging-isolation.test.mjs`: يغطي غياب إعداد Preview، ومطابقة قاعدة الإنتاج، ومخالفة allowlist، والاتصال المعزول.
- `docs/STAGING_ISOLATION_AND_CATALOG_TRANSFER_AR.md`: يوثق أن إعداد Preview الحالي غير معزول بعد، وأن الاتصال لن يعمل حتى توفير قاعدة Preview مستقلة.

## قاعدة البيانات والنسخ الاحتياطية

- Vercel Pro والدومين الرسمي متاحان. مشروع Staging الحالي ومخزن Blob الخاص به محفوظان؛ لا توجد قاعدة Staging ولا نشر Staging.
- تكامل Prisma الظاهر حالياً Free وغير مربوط صراحةً بمشروع Vercel، ولا يثبت وجود قاعدة الإنتاج أو موقعها أو نسختها الاحتياطية. لا أُجريت ترقية مدفوعة؛ لا يوجد دليل كافٍ لتحديد مورد الإنتاج الذي يمكن ترقيته بأمان.
- لم تُشغّل استعلامات أو ترحيلات على الإنتاج. ترحيلات الفرع reviewed لا تحتوي إسقاط جداول أو حذف صفوف؛ يلزم تطبيقها أولاً على قاعدة اختبار/نسخة مستعادة، مع فحص الانحراف والقيود.
- قبل أي ترحيل إنتاج: تحديد المورد الصحيح، أخذ نسخة مشفرة، استعادة النسخة في قاعدة منفصلة، التحقق من أعداد/علاقات البيانات، تجربة الترحيلات وفحوص ما بعد الترحيل، وتوثيق أمر التراجع. هذه الخطوات لم تُنفذ لعدم وجود قاعدة اختبارية مستقلة أو إثبات نسخة احتياطية.

## سجل المخاطر

### مانعة للنشر

1. Preview يستخدم حالياً نفس متغيرات قاعدة البيانات التي يستخدمها Production. حارس الفرع يمنع ذلك عند وصوله للتشغيل، لكن الإعداد البعيد لم يتغير ولم يُختبر في Preview.
2. قاعدة الإنتاج وموقعها وخطة النسخ الاحتياطي/الاستعادة غير متحقق منها. لا يمكن اعتماد أي ترحيل إنتاج.
3. بناء الإنتاج لم يكتمل محلياً بسبب قيد بيئة التنفيذ، واختبارات قاعدة البيانات لم تتوفر لها قاعدة محلية مستقلة. يلزم تحقق CI ناجح على Commit المرشح.
4. فرع المراجعة ليس إصداراً موحداً بعد: هو متشعب عن `main` بفارق 615 Commit مقابل 2. لا يجوز استبدال `main` به دون مراجعة الاختلافات والاختبارات وخطة ترحيل معتمدة.
5. مراجعة الشركاء وتجديد التراخيص كانت ترسل صور المستندات وحقولاً تعريفية إلى Gemini عند ضبط المفتاح. خُفّضت الحقول المرسلة وأصبح الإرسال متوقفاً افتراضياً؛ تفعيل `AI_DOCUMENT_PROCESSING_APPROVED=true` يحتاج مراجعة شروط الحساب المدفوع والاحتفاظ والإشعار/الموافقة.

### غير مانعة منفردة

- 71 تحذيراً في ESLint دون أخطاء.
- تحسينات شكلية وأداء صور/تنقل يمكن متابعتها بعد الإطلاق بعد إغلاق الموانع أعلاه.

## خطة الإصدار والتراجع

1. الاحتفاظ بنشر `main` الحالي كنقطة رجوع، وعدم تغيير الدومين.
2. دمج التغييرات لاحقاً عبر Pull Request مراجَع بعد حل الانحراف بين الفروع وتشغيل GitHub CI كاملة على قاعدة مؤقتة.
3. إعداد قاعدة Preview منفصلة في نطاق Preview وحده، ثم إثبات العزل عبر فحوص اتصال، ورفض اختبارات URL الإنتاج، وتأكيد عدم وجود أسرار دفع أو بيانات شخصية.
4. قبل ترحيل الإنتاج: التحقق من مورد الإنتاج، نسخة احتياطية مشفرة، واستعادة تجريبية. لا يسمح للبناء بإجراء ترحيل تلقائي.
5. بعد موافقة صريحة على النشر/الترحيل، تطبيق خطة تغيير مُعتمدة مع فحوص التسجيل، اعتماد الشريك، نشر الخدمة، الصلاحيات والتراخيص.
6. إذا فشلت صحة التطبيق، أعد توجيه الدومين إلى نشر Vercel السابق. إذا اكتُشف خلل بيانات، أوقف الكتابات ثم استعد النسخة الاحتياطية وفق نافذة الصيانة المعتمدة؛ لا تُجرى استعادة تلقائية فوق بيانات أحدث.

**لم يتم الدمج أو الرفع أو النشر أو تعديل Vercel أو قاعدة بيانات الإنتاج أو أي مورد مدفوع.**
